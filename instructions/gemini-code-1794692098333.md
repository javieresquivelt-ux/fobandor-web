# BLOQUE 3: STACK TECNOLÓGICO E INFRAESTRUCTURA AGNÓSTICA
# ==============================================================================
* **Backend:** Python 3.12+ y Django 5.x (con modelo `CustomUser` desde la migración inicial, diferenciando staff interno de clientes registrados).
* **Base de Datos:** PostgreSQL 16+ usando el ORM nativo de Django (`USE_TZ = True` en UTC; conversión visual a `America/New_York` para operación de Orlando).
* **Gestión de Archivos / Media:** Manejo seguro de imágenes y entregables (`Pillow`, `MEDIA_ROOT` / `MEDIA_URL`) para logos, proyectos, servicios y paquetes digitales.
* **Frontend (100% Server-Driven, SIN React/Vue):**
  * Motor de plantillas: Django Template Language (DTL) nativo modularizado en `partials/`.
  * Reactividad HTTP: **HTMX** (`hx-get`, `hx-post`, `hx-put`, `hx-delete`, `hx-target`, `hx-swap`) para sitio público, portal del cliente y Backoffice.
  * Micro-interactividad cliente: **Alpine.js** (exclusivamente para estado visual efímero: toggle dark/light mode, menús móviles, modales, notificaciones toast y selectores como Flatpickr).
  * Estilos: **Tailwind CSS** (`darkMode: 'class'`).
* **Pasarela de Pagos y Suscripciones:** **Stripe** mediante:
  * **Stripe Checkout** (`mode='subscription'` con soporte para `allow_promotion_codes=True` para cupones de descuento).
  * **Stripe Customer Portal** (`stripe.billing_portal.Session.create`) para autogestión y cancelación de suscripciones por parte del cliente.
  * **Webhooks Firmados (`/stripe/webhook/`):** Escucha obligatoria de `checkout.session.completed`, `invoice.paid`, `invoice.payment_failed` y `customer.subscription.deleted` / `updated`.
* **Entorno de Desarrollo, Demos y Despliegue:**
  * **Desarrollo y Demos al Cliente:** Ejecución local en **Linux Ubuntu (`localhost`)**, donde se mostrarán los avances funcionales de cada etapa al cliente.
  * **Control de Versiones:** Repositorio sincronizado en **GitHub**.
  * **Producción (Hosting Agnóstico):** El proveedor VPS definitivo está pendiente de selección por el cliente. La aplicación debe construirse 100% agnóstica de proveedor bajo estándar **12-Factor** (`django-environ`, variables `.env`) y lista para contenedores (**Docker / Gunicorn / Nginx**).

# BLOQUE 4: REQUERIMIENTOS FUNCIONALES Y REGLAS DE NEGOCIO
# ==============================================================================
1. **Full Responsive:** Diseño *mobile-first* adaptado a móviles, tablets y escritorio en la web pública, portal de cliente y Backoffice.
2. **Multi-idioma (i18n):** Español (idioma por defecto) e Inglés mediante el sistema nativo de internacionalización de Django (`{% trans %}`, `{% blocktrans %}`) y campos bilingües (`_es` / `_en`) en los modelos dinámicos.
3. **Tema Claro / Oscuro:** Implementado con Tailwind (`darkMode: 'class'`) y persistido en `localStorage` vía Alpine.js, respetando la estética dark-tech de FOBANDOR.
4. **SEO Técnico:** Meta etiquetas dinámicas por vista/contenido, Open Graph, etiquetas semánticas HTML5, `sitemap.xml` dinámico y `robots.txt`.
5. **Modelo de Precios, Cupones y Ciclo de Entrega a 7 Días (Lógica Core de Negocio):**
   * **3 Planes Iniciales Administrables:** Tabla comparativa de 3 planes mensuales configurables desde el Backoffice (vinculados a su respectivo `stripe_price_id`, características en ES/EN y estado activo/destacado).
   * **Cupones de Descuento:** Soporte nativo para códigos promocionales/cupones de Stripe aplicables durante el checkout para clientes seleccionados.
   * **Flujo Prepago + SLA de 7 Días + Renovación Mensual:**
     1. El cliente paga por adelantado al suscribirse.
     2. Al confirmarse el pago inicial (`checkout.session.completed`) o cada renovación mensual (`invoice.paid`), el sistema crea automáticamente una **Orden de Entrega (`FulfillmentOrder`)** en PostgreSQL con fecha límite `due_date = paid_at + 7 días` y estado `PENDIENTE_PRODUCCION`.
     3. El equipo de FOBANDOR visualiza la cola de entregas pendientes en el Backoffice (con alerta de días restantes) y carga el enlace/paquete digital para redes sociales dentro del plazo de 7 días, marcando la orden como `ENTREGADA` y notificando al cliente.
     4. Mientras el cliente no cancele su suscripción, al mes siguiente Stripe ejecuta el cobro recurrente y dispara un nuevo ciclo automático de 7 días para su nuevo paquete mensual de redes sociales.
6. **Registro de Clientes, Activación Obligatoria y Mantenedor de Clientes (CRM):**
   * **Activación Antes de Pagar (Gate de Seguridad):** Todo cliente debe registrarse y **activar su cuenta mediante enlace de verificación enviado a su correo electrónico** (`is_email_verified=True`) *antes* de poder iniciar una sesión de pago en Stripe Checkout.
   * **Datos a Solicitar en el Registro (Estándar Industria / PCI-DSS & AVS):**
     * *Identidad y Acceso:* Correo electrónico único (usuario de acceso), contraseña segura (con flujo de recuperación), Nombre (`first_name`) y Apellidos (`last_name`).
     * *Contacto:* Teléfono móvil en formato internacional E.164 (ej. `+1...`).
     * *Datos Comerciales / B2B (Opcionales):* Nombre de empresa/marca (`company_name`), sitio web/arroba de redes sociales (`social_handle`) y Tax ID / EIN / NIF (`tax_id`).
     * *Dirección de Facturación (Requerida para AVS de Stripe y cálculo fiscal):* País (ISO 3166-1 alpha-2), Estado/Provincia, Ciudad, Código Postal (ZIP Code) y Dirección (Línea 1 y Línea 2).
     * *Sincronización Stripe (PCI-DSS):* Campo `stripe_customer_id` creado/vinculado vía API de Stripe al activar la cuenta. **Prohibido almacenar números de tarjeta, CVV o fechas de expiración en la BD local.**
     * *Cumplimiento Legal:* Idioma preferido (`es`/`en`), aceptación explícita de Términos y Política de Privacidad con marca de tiempo (`terms_accepted_at`), y opt-in opcional de marketing (`marketing_consent`).
   * **Mantenedor de Clientes en Backoffice (`/backoffice/customers/`):** Búsqueda reactiva (HTMX), filtros por estado de cuenta/suscripción, edición de datos, suspensión/activación, gestión de entregas de paquetes digitales (SLA 7 días) e historial de facturas Stripe.
7. **Portal de Autoservicio del Cliente (`/mi-cuenta/`):**
   * Área privada protegida (`LoginRequiredMixin`) donde el cliente autenticado puede editar sus datos de perfil/facturación, descargar sus paquetes digitales mensuales entregados y abrir el **Stripe Customer Portal** para gestionar su método de pago o cancelar/reactivar su suscripción.
8. **Mantenedor de Usuarios Internos (RBAC) y CMS Propio (`/backoffice/`):**
   * Control de acceso basado en roles (`Groups` y `Permissions` de Django) para staff interno (`is_staff=True`):
     * *Superadministrador:* Gestión de usuarios internos y perfiles, configuración global, planes/cupones, clientes, cola de entregas y transacciones Stripe.
     * *Editor de Contenido:* CRUD completo sobre contenidos bilingües de la web (Hero, Servicios, Proyectos, Nosotros, enlaces oficiales de RRSS), sin acceso a finanzas ni usuarios.
     * *Operador de Entregas / Studio (opcional):* Acceso a la cola de `FulfillmentOrder` para subir y entregar los paquetes mensuales dentro del SLA de 7 días.
   * Panel construido 100% con DTL + HTMX + Alpine.js + Tailwind CSS con auditoría (`created_by`, `updated_by`, `updated_at`) y precarga inicial (`seed_initial_content`) de las 4 líneas de servicio y las redes sociales oficiales de FOBANDOR.
